# Hark M6 - Fathom Parity and Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gaps found in the 0.1.0 review: long-meeting summaries, semantic chat retrieval, auto-titles, attendee names, calendar context, other languages, a screen-source picker, re-run/retry controls with visible errors, an auto-updater, an outbound webhook, more meeting-app patterns, and a lighter first-run download.

**Architecture:** Every feature stays local-only and manual-by-design. New pure logic goes in crates with unit tests (`hark-llm::{chunked,title,embed}`, `hark-store::{vectors,participants}`, `hark-calendar`, `hark-detect::participants`); `src-tauri` glue gains a `variant` build constant for the updater and a small `webhook` module. UI changes are additive on the existing routes.

**Tech Stack:** as 0.1.0 plus `tauri-plugin-updater` + `tauri-plugin-process`, llama.cpp embeddings via `llama-cpp-2` (`bge-small-en-v1.5` GGUF), Win32 UI Automation (`windows` crate, `Win32_UI_Accessibility`).

## Global Constraints
- No new network calls except ones the user configures (calendar URLs, webhook URL, updater manifest on GitHub). Document each in `docs/privacy.md`.
- Nothing records, renames a speaker, or shares without a click. Attendee names are *suggestions* in the rename picker, never auto-applied.
- Every stage still fails soft; a failed stage stores a human-readable `error` on the meeting and the UI shows it with a Retry.
- Version bumps to 0.2.0 (`package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `CHANGELOG.md`).

### Task 1: hark-llm - chunked summary + auto-title
- `summary::generate` keeps its signature but, when `vars.transcript.len() > max_chars`, calls `chunked::notes_for_blocks(backend, transcript, block_chars)`: split on line boundaries into blocks <= `block_chars` (20k), ask the model for dense bullet notes per block (`CHUNK_NOTES_SYSTEM`, "Part N of M, mm:ss-mm:ss"), then render the template with `{{transcript}}` = joined notes and a `[Condensed from N parts]` marker. Progress callback `on_progress(part, total)`.
- `title::generate(backend, transcript_head: &str, app_label: Option<&str>) -> Result<String>`: <= 8 words, no quotes/trailing period, falls back to `None` on empty/garbage (`sanitize_title`). Uses first ~6k chars.
- Tests: block splitting never splits a line and respects the size; `sanitize_title` strips quotes, "Title:", trailing punctuation, truncates to 80 chars; chunked path calls backend `N+1` times (fake backend counting calls).

### Task 2: store - meeting error/title flags, participants, vectors (migration v5)
- `meetings` += `error TEXT`, `title_auto INTEGER DEFAULT 1` (0 once the user renames), `participants_json TEXT DEFAULT '[]'`, `calendar_uid TEXT`.
- `chunk_vectors(chunk_id INTEGER PK REFERENCES chunks(id) ON DELETE CASCADE, dim INTEGER, vec BLOB)`.
- API: `set_meeting_error(id, Option<String>)`, `set_participants(id, &[String])`, `Meeting.participants: Vec<String>`, `Meeting.title_auto: bool`, `Meeting.error: Option<String>`, `rename_meeting` sets `title_auto = 0`; `set_chunk_vectors(meeting_id, &[(chunk_id, Vec<f32>)])`, `chunks_without_vectors(meeting_id) -> Vec<(i64, String)>`, `search_chunks_vec(query: &[f32], scope, limit) -> Vec<ChunkHit>` (brute-force cosine over the scope; `fable:` index when > ~200k chunks), `fuse_hits(bm25: Vec<ChunkHit>, vec: Vec<ChunkHit>, limit) -> Vec<ChunkHit>` = reciprocal rank fusion (k=60) keyed by (meeting_id,start_ms).
- Tests: migration adds columns; vector search ranks the nearest chunk first; RRF interleaves.

### Task 3: hark-llm embeddings + catalog + pipeline wiring
- `embed.rs`: `EmbedEngine::load(path) -> Self`, `embed(&self, texts: &[&str]) -> Result<Vec<Vec<f32>>>` (llama-cpp-2 context with `embeddings(true)`, mean pooling, L2-normalised; batches of 16; `"query: "`/`"passage: "` prefixes not needed for bge). `dim()`.
- `catalog.json` += `{ id: "bge-small-en-v1.5-q8", kind: "embed", file: "bge-small-en-v1.5-q8_0.gguf", url: "https://huggingface.co/CompendiumLabs/bge-small-en-v1.5-gguf/resolve/main/bge-small-en-v1.5-q8_0.gguf", sha256: <computed>, size_bytes: <actual> }` and `common` gets `embed`.
- `AppState.engines.embed: Option<(String, Arc<EmbedEngine>)>`, `state.embed()` lazy-loads if downloaded; idle unloader covers it.
- Pipeline: after `rebuild_chunks` -> `embed_stage::embed_meeting(app, id)` (skips silently if no embed model). `send_chat`: `hits = fuse(search_chunks(q), search_chunks_vec(embed(q)))` when embed is available, else BM25 only.
- Settings UI: model list shows the embedding model under "Search"; `docs/models.md` gains a row.

### Task 4: re-run controls, retry, visible errors
- Commands: `retranscribe(id)` (exists) now takes `model: Option<String>`; new `rediarize(id)`, `recleanup(id)`, `reembed(id)`; `post_process` sets `meeting.error` on `fail` and clears it on success; every stage error is appended to `error` when the stage fails soft (`"summary: ..."`).
- Meeting page: a "Processing" card when status != Ready, showing stage + progress; when Failed shows the error text and **Retry** (full re-run) plus a "..." menu with Re-transcribe (model picker), Re-detect speakers, Re-clean, Re-embed, Regenerate summary.
- Events unchanged (`processing` payload already has `error`).

### Task 5: attendee names (Windows UIA) + rename suggestions
- `hark-detect::participants`: `pub fn extract_names(app: &str, raw: &[String]) -> Vec<String>` pure: per-app heuristics (Zoom tiles/participant rows, Teams "Name, ..." roster items, Meet "Name" + "(You)"/"presentation" stripping, Discord "Name, speaking"), generic filters (2..=4 words, letters/apostrophes/hyphens, not a UI word from a stoplist, dedupe case-insensitively, cap 50). `pub fn scrape_window(hwnd: isize) -> Vec<String>` (Windows: `IUIAutomation::ElementFromHandle` + `FindAll(TreeScope_Descendants, TrueCondition)` with a cache request for Name, capped 2000 elements; other OSes: empty). `WindowInfo` gains `hwnd: isize`.
- Recorder: when started from a detection (opts.app set), spawn a sampler thread every 45 s that finds the meeting window by pattern, scrapes, merges into `participants` (union), saves via `set_participants`, emits `participants_changed`.
- UI: attendee chips on the meeting header; `SpeakerChip` rename input gets a datalist of attendees + known speakers; "Me" excluded. Summary `participants` var = union of labels and attendees.
- Tests: `extract_names` fixtures for Zoom/Teams/Meet raw name lists.

### Task 6: calendar (.ics)
- New crate `hark-calendar`: `parse_ics(src: &str) -> Vec<CalEvent { uid, title, start: DateTime<Utc>, end, attendees: Vec<String>, url: Option<String> }>` (unfold lines, DTSTART/DTEND with `TZID=`, `VALUE=DATE`, `Z`; ATTENDEE CN=; ORGANIZER CN=; skip RRULE except weekly with no UNTIL/COUNT expanded 8 weeks ahead - `fable:`). `events_around(events, now, before=10min, after=2h) -> Vec<CalEvent>`; `best_match(events, now) -> Option<&CalEvent>` = overlapping event with the nearest start.
- Settings += `calendar_sources: Vec<String>` (https URLs or file paths), `calendar_refresh_min: 15`. `calendar.rs` in src-tauri: background refresh, cache in `AppState.calendar: RwLock<Vec<CalEvent>>`, `list_upcoming` command.
- Recorder start: if `best_match` -> title = event title, participants seeded with attendee names, `calendar_uid`. Popup: shows the matched event title under the app name. Library: "Today" strip of upcoming events with a Record button.
- Tests: parsing Google + Outlook style samples, TZID conversion, weekly expansion count, matching window.

### Task 7: multi-language
- Settings `language: Option<String>` where `None` = auto-detect (whisper `set_language(None)` + `detect_language`), explicit code otherwise. Onboarding + Settings select with 30 common languages + Auto.
- Prompts: cleanup/summary/title/chat system prompts append `"Write in the same language as the transcript."`; `cleanup` keeps English few-shot but adds a one-line note.
- Tests: `hark-asr` param builder accepts None; prompt strings contain the sentence.

### Task 8: screen source picker + popup placement
- `hark-capture::video::list_sources() -> Vec<VideoSource { target: VideoTarget, label: String, is_meeting: bool }>`: monitors (Windows `EnumDisplayMonitors` with `GetMonitorInfoW`; macOS `ffmpeg -f avfoundation -list_devices` parse, fallback "Display 1"), plus visible windows from `hark-detect::list_visible_windows` (top 30 by title). Command `list_video_sources`.
- Popup: "Screen" select defaulting to the detected meeting window (or last choice from settings `video_target`); passes `target` in `StartOptions`.
- Popup window placement: `windows.rs` positions the popup on the monitor containing the meeting window (`MonitorFromWindow`) bottom-right with 16 px margin; DPI-aware via `tauri` monitor API (`window.current_monitor()` fallback).

### Task 9: webhook
- Settings += `webhook_url: String`, `webhook_enabled: bool`. `webhook.rs`: `fire(app, meeting_id)` POSTs `{ event: "meeting.ready", meeting, summary, transcript: [ {start_ms,end_ms,speaker,text} ], participants }` with `User-Agent: Hark/<ver>`; 10 s timeout; failure = notice, never retried automatically. Command `test_webhook` sends `{event:"test"}`.
- Called at the end of `post_process` (after summary). Settings UI: URL field, toggle, Test button; `docs/privacy.md` note.

### Task 10: more app patterns
- `patterns.toml` += Zoom web (`app.zoom.us`), Teams web (`teams.microsoft.com`, `teams.live.com`), Webex web, Whereby, Jitsi (`meet.jit.si`), Around, Skype, RingCentral, BlueJeans, Gather, Butter, WhatsApp call, Telegram call, Signal call, Zoom localized titles ("Reunión de Zoom", "Réunion Zoom"), Meet localized ("Meet – "). Test each with a fixture window list.

### Task 11: auto-updater
- Generate a minisign keypair with `pnpm tauri signer generate -w ~/.tauri/hark.key` (private key stays on this machine + GitHub secret `TAURI_SIGNING_PRIVATE_KEY`; pubkey in `tauri.conf.json` `plugins.updater.pubkey`).
- `build.rs` exposes `HARK_VARIANT` (`cpu`|`cuda`|`metal`|default `cpu`); runtime endpoints `https://github.com/Dallenlol/hark/releases/latest/download/latest-<variant>.json` via `tauri_plugin_updater::Builder::new().endpoints(...)`.
- `release.yml`: pass `TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD` to tauri-action; collect `.sig` files; a final `manifest` job downloads all artifacts and writes `latest-cpu.json` (windows-x86_64 -> cpu nsis), `latest-cuda.json` (windows-x86_64 -> cuda nsis), `latest-metal.json` (darwin-aarch64 -> arm dmg... updater needs `.app.tar.gz`: enable `bundle.createUpdaterArtifacts: true` and upload the `.tar.gz` + `.sig`), uploaded to the release.
- App: check on startup (after 20 s) and via Settings "Check for updates"; toast "Hark 0.x is available - Install" -> download+install+relaunch. Settings toggle `auto_update_check` (default on).

### Task 12: lighter onboarding
- Onboarding downloads only `asr_live` + `embed` first ("Start now"), then queues the quality ASR + LLM in the background with a progress pill in the sidebar; the meeting page states "Summary will run when the language model finishes downloading" and the pipeline's summary/cleanup stages re-run automatically for meetings that were skipped for that reason (`error` starts with `"no-llm:"`).

### Task 13: polish + release
- Accessibility pass: every icon-only `Button` gets `aria-label`; focus-visible ring token; popup buttons reachable by Tab; `Esc` dismisses popup.
- Live captions: keep the last partial line in place (replace instead of append) - `Transcript` live mode diffs on `start_ms`.
- Docs: README feature list, `docs/privacy.md` (calendar/webhook/updater), `docs/faq.md`, `CHANGELOG.md` 0.2.0, site download page notes "auto-updates". Version bump. Tag `m6`, tag `v0.2.0`, let CI publish the draft.
