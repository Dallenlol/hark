# Hark M3 - Summaries, Templates, Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every finished meeting gets an instant structured summary from a (user-editable) template, and the user can chat with the local model about one meeting or the whole library, with timestamp citations that seek the player.

**Architecture:** `hark-llm` gains `summary` (template rendering + markdown-section parsing) and `chat` (retrieval prompt + citation parsing). Retrieval is FTS5/BM25 over transcript segments grouped into ~45 s chunks (`hark-store::chunks`). Streaming replies go to the UI as `chat_token` events. Templates are markdown files with a small header, stored in the DB (built-ins seeded on first run).

## Global Constraints
- Summary generation never blocks Ready; it runs after cleanup and can be re-run with any template.
- Chat answers must cite `[m:ss]` timestamps taken from retrieved chunks only; the UI turns them into seek buttons.
- `fable:` retrieval is BM25-only in M3; embedding search is a follow-up (trait boundary `Retriever` kept).

### Task 1: store - templates, summaries, chats, chunks (migration v3)
- Tables: `templates(id, name, description, body, builtin INTEGER, created_at)`, `summaries(meeting_id PK, template_id, markdown, structured_json, model, created_at)`, `chats(id, scope_kind, scope_id, title, created_at)`, `chat_messages(id, chat_id, role, content, citations_json, created_at)`, `chunks(id, meeting_id, start_ms, end_ms, text)` + `chunks_fts` (external content, text).
- API: `list_templates/upsert_template/delete_template`, `set_summary/get_summary`, `create_chat/list_chats/delete_chat/add_message/messages`, `rebuild_chunks(meeting_id)` (from clean_text else text, 45 s windows), `search_chunks(query, scope: Option<meeting_id>, limit) -> Vec<ChunkHit{meeting_id, meeting_title, start_ms, end_ms, text, rank}>`.
- Tests: chunking window sizes; scoped vs global search; summary upsert; chat message ordering.

### Task 2: hark-llm - templates, summary, chat
- `templates/` built-ins: general, sales-call, client-discovery, one-on-one, standup, interview. Format: first line `# Name`, a `> description` line, then the prompt body with placeholders `{{title}} {{date}} {{participants}} {{duration}} {{transcript}} {{highlights}}`.
- `summary::render(template_body, vars) -> String`; `summary::generate(backend, rendered_prompt) -> SummaryResult { markdown, structured }` where structured = sections parsed by `## ` headings into `{summary, action_items[], decisions[], open_questions[], key_moments[{ms?, text}]}` (tolerant).
- `chat::build_messages(question, history, chunks, scope_desc) -> Vec<ChatMessage>`; `chat::parse_citations(answer) -> Vec<{ms, meeting_id?}>` (matches `[m:ss]`/`[h:mm:ss]` and `[m:ss @ <meeting-id-prefix>]`).
- Tests: rendering, section parsing on messy output, citation parsing.

### Task 3: app - pipeline + commands + events
- Pipeline: after cleanup -> `rebuild_chunks` -> `summary` stage (default template = settings.default_template_id or "general") -> `summaries`.
- Commands: `list_templates`, `save_template`, `delete_template`, `generate_summary(id, template_id)`, `get_summary(id)`, `list_chats(scope_kind, scope_id)`, `create_chat`, `delete_chat`, `chat_messages(chat_id)`, `send_chat(chat_id, text)` (spawns thread; emits `chat_token{chat_id,message_id,delta}` then `chat_done{chat_id,message}`), `cancel_chat(chat_id)`.
- Settings += `default_template_id`, `summary_enabled`.

### Task 4: UI
- Meeting page: tabs Transcript | Summary | Chat. Summary: rendered markdown (tiny renderer: headings, lists, bold), template picker + Regenerate. Chat: message list, streaming assistant bubble, citations as `[m:ss]` buttons that seek.
- Sidebar: "Ask Hark" route (`/ask`) = chat over all meetings, citations open the meeting at time.
- Settings: Templates section (list, edit in a textarea with placeholder help, add/duplicate/delete; built-ins can be duplicated not deleted).
- Tests: markdown renderer, citation button rendering.

### Task 5: verify
- Smoke prints summary markdown and one chat answer for "What was said about the country?" with a citation. Tag `m3`.
